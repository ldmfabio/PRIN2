## 1. A ponte entre Banco de Dados e Desenvolvimento Web

Na disciplina de Banco de Dados, você executa SQL no Workbench. Em uma aplicação web, o usuário normalmente interage com uma tela. Essa tela envia uma requisição ao backend, que pode executar SQL e devolver uma resposta.

Nesta aula, utilizaremos os conhecimentos de SQL para construir esse caminho. A tabela não será substituída: passará a ser acessada também por uma API.

| Componente                | Responsabilidade                                        | Nesta aula                                                              |
| ------------------------- | ------------------------------------------------------- | ----------------------------------------------------------------------- |
| Cliente                   | Enviar requisições e receber respostas                  | Swagger UI no navegador                                                 |
| Frontend                  | Apresentar a interface com a qual o usuário interage    | Usaremos a interface do Swagger; criaremos nosso frontend em outra aula |
| Backend                   | Validar dados e processar as operações                  | Python com FastAPI                                                      |
| SGBD                      | Executar SQL e gerenciar os dados                       | MySQL Server                                                            |
| Ferramenta administrativa | Permitir administrar o banco e executar SQL manualmente | MySQL Workbench                                                         |

O Workbench é um cliente do banco; ele não precisa ficar aberto para a API funcionar. O serviço MySQL Server precisa estar em execução.

O Swagger **não envia SQL diretamente ao MySQL**. Ele envia HTTP à API; o código Python decide qual SQL executar.

### 1.1. API e contrato

Uma API é uma interface pela qual programas podem interagir. Uma API HTTP estabelece endereços, métodos, dados de entrada e respostas esperadas.

Exemplo de contrato:

> Para consultar os produtos, envie GET para `/produtos`. Para criar um produto, envie POST para o mesmo caminho com os dados em JSON.

Chamamos de **endpoint** uma combinação de método e caminho disponibilizada pela API. `GET /produtos` e `POST /produtos` são operações diferentes.

### 1.2. HTTP, requisição e resposta

Uma requisição é uma mensagem que o cliente envia ao servidor. Uma resposta é a mensagem que o servidor devolve.

| Parte da requisição      | Exemplo                          | Para que serve                  |
| ------------------------ | -------------------------------- | ------------------------------- |
| Método                   | `GET`                            | Expressa a intenção da operação |
| URL                      | `http://127.0.0.1:8000/produtos` | Indica o destino                |
| Cabeçalhos               | `Accept: application/json`       | Informam metadados              |
| Corpo, quando necessário | JSON de um novo produto          | Envia dados da operação         |

| Parte da resposta       | Exemplo                          | Para que serve                           |
| ----------------------- | -------------------------------- | ---------------------------------------- |
| Status HTTP             | `200 OK`                         | Informa o resultado geral                |
| Cabeçalhos              | `Content-Type: application/json` | Descrevem o conteúdo e outros metadados  |
| Corpo, quando existente | Lista de produtos em JSON        | Apresenta dados ou detalhes do resultado |

No endereço `http://127.0.0.1:8000/produtos`, `http` é o protocolo, `127.0.0.1` identifica o próprio computador, `8000` é a porta da API e `/produtos` é o caminho. O MySQL normalmente utiliza outra porta, `3306`.

### 1.3. REST e recursos

REST é um estilo arquitetural para sistemas distribuídos. Em APIs HTTP, trabalhamos com recursos identificados por endereços e representados em formatos como JSON.

Nosso recurso será o produto:

- `/produtos`: coleção de produtos.
- `/produtos/3`: produto identificado pelo número 3.

Em vez de um caminho `/buscarProduto`, usamos um método com significado: `GET /produtos/3`.

Algumas ideias de REST:

- **Cliente e servidor separados:** a interface pode mudar sem substituir o banco ou a lógica da API.
- **Requisições sem estado de sessão:** cada mensagem deve trazer o necessário para ser compreendida. O servidor não depende de o cliente ter dito, em uma requisição anterior, qual produto deseja consultar. Isso não impede a persistência de dados no banco.
- **Interface uniforme:** métodos, endereços e respostas seguem significados consistentes.
- **Representações:** o JSON é uma representação do produto.
- **Cache e camadas:** respostas podem informar regras de cache; intermediários podem participar da comunicação.

Construir um CRUD com JSON é uma introdução prática, mas não é, por si só, toda a definição de REST.

### 1.4. Métodos HTTP

| Método | Intenção usual neste projeto              | Exemplo                        |
| ------ | ----------------------------------------- | ------------------------------ |
| GET    | Consultar                                 | Listar produtos                |
| POST   | Criar na coleção                          | Cadastrar produto              |
| PUT    | Substituir os campos editáveis do recurso | Enviar nome, categoria e preço |
| PATCH  | Alterar parcialmente                      | Enviar apenas novo preço       |
| DELETE | Remover                                   | Excluir produto                |

Nesta aula, implementaremos **GET e POST**. Os demais serão construídos depois.

GET não deve ser usado para solicitar alterações no banco. Repetir um POST de cadastro pode criar outro registro. Não existe uma equivalência obrigatória entre verbo e SQL: uma operação pode executar vários comandos ou nem utilizar um banco.

## 2. Por que FastAPI?

O FastAPI é um framework Python para construir APIs. Nesta aula, permite descrever rotas com pouco código, validar entradas e gerar uma interface de documentação para testes.

A escolha favorece a observação do percurso **HTTP → Python → SQL → JSON**, sem exigir a construção de telas logo no início. A documentação interativa permite testar o backend independentemente do frontend.

Usaremos SQL explícito para reconhecer comandos já vistos em Banco de Dados. Posteriormente, poderemos estudar ORM e comparar as duas abordagens.

## 4. Preparar o MySQL

### 4.1. Criar banco, tabela e usuário

Abra uma conexão administrativa no Workbench. Execute o SQL abaixo nessa conexão, e não no PowerShell. Os comandos `CREATE USER` e `GRANT` exigem permissão administrativa.

```sql
CREATE DATABASE IF NOT EXISTS aula_rest CHARACTER SET utf8mb4;
USE aula_rest;

CREATE TABLE IF NOT EXISTS produtos (
    id INT AUTO_INCREMENT PRIMARY KEY,
    nome VARCHAR(100) NOT NULL,
    categoria VARCHAR(50) NOT NULL,
    preco DECIMAL(10, 2) NOT NULL,
    CONSTRAINT chk_produtos_preco CHECK (preco >= 0)
) ENGINE=InnoDB;

| Elemento         | Significado                                                            |
| ---------------- | ---------------------------------------------------------------------- |
| `aula_rest`      | Banco utilizado pela API                                               |
| `utf8mb4`        | Conjunto de caracteres que suporta acentos e outros caracteres Unicode |
| `AUTO_INCREMENT` | O banco gera o ID                                                      |
| `PRIMARY KEY`    | Identifica cada produto                                                |
| `VARCHAR`        | Texto com tamanho limitado                                             |
| `NOT NULL`       | O campo não aceita ausência de valor no banco                          |
| `DECIMAL(10, 2)` | Até dez dígitos, sendo dois após a casa decimal                        |
| `CHECK`          | Restringe preços negativos em versões que aplicam essa restrição       |
| `InnoDB`         | Motor que permite trabalhar com transações                             |

Considere MySQL 8.0.16 ou superior para aplicação efetiva do `CHECK`. Também validaremos o preço na API.

O usuário `api_aula` terá permissões de leitura e alteração, mas não precisará administrar o servidor. A senha apresentada é um exemplo para o laboratório local. O `IF NOT EXISTS` **não atualiza a senha de um usuário que já existia**; nesse caso, utilize a senha correta ou solicite ao administrador o ajuste.

## 6. Construir o acesso ao banco: primeiro, apenas leitura

### 6.1. Conexão e cursor

A **conexão** é o canal de comunicação entre o programa Python e uma sessão no MySQL.

O **cursor** é um objeto do driver utilizado para enviar comandos por essa conexão e recuperar resultados. Ele não é o ponteiro do mouse e não precisa ser um cursor declarado com `DECLARE CURSOR` em SQL.

O percurso de uma leitura será:

1. Abrir uma conexão.
2. Criar um cursor.
3. Executar SQL com `cursor.execute`.
4. Recuperar os registros com `cursor.fetchall`.
5. Fechar cursor e conexão.

### 6.2. Criar `database.py`

Crie o arquivo `database.py` na raiz do projeto e insira:

```python
import os
from pathlib import Path

import mysql.connector
from dotenv import load_dotenv

load_dotenv(Path(__file__).with_name(".env"))


def executar_sql(sql, parametros=()):
    conexao = mysql.connector.connect(
        host=os.environ["DB_HOST"],
        port=int(os.environ["DB_PORT"]),
        database=os.environ["DB_NAME"],
        user=os.environ["DB_USER"],
        password=os.environ["DB_PASSWORD"],
    )

    cursor = None

    try:
        cursor = conexao.cursor(dictionary=True)
        cursor.execute(sql, parametros)
        return cursor.fetchall()

    finally:
        if cursor is not None:
            cursor.close()
        conexao.close()
```

### 6.3. Entender o código

`import` permite utilizar código de outros módulos. `mysql.connector` e `dotenv` vêm dos pacotes instalados; `os` e `pathlib` fazem parte da biblioteca padrão do Python.

```python
load_dotenv(Path(__file__).with_name(".env"))
```

`__file__` representa o caminho deste arquivo Python. `with_name(".env")` encontra o `.env` na mesma pasta. `load_dotenv` carrega suas configurações. Variáveis já definidas no ambiente têm prioridade por padrão.

```python
def executar_sql(sql, parametros=()):
```

`def` define uma função. A função reúne um procedimento para reutilizá-lo em várias rotas.

- `sql`: texto do comando a executar.
- `parametros`: valores utilizados pelos marcadores do SQL.
- `=()` indica que o padrão é uma tupla vazia: nenhuma entrada adicional.

Python utiliza **indentação** para indicar blocos. Mantenha quatro espaços por nível; o VSCode normalmente ajuda nesse alinhamento.

```python
conexao = mysql.connector.connect(...)
```

Abre a conexão utilizando as configurações. `os.environ["DB_PORT"]` lê texto; `int(...)` o converte para inteiro. As reticências nesta explicação representam o trecho já apresentado; não substitua o código do arquivo por elas.

```python
cursor = conexao.cursor(dictionary=True)
```

Cria o cursor. `dictionary=True` retorna cada linha como um dicionário, com nomes de colunas como chaves. Exemplo em Python:

```python
{"id": 1, "nome": "Caderno", "categoria": "Papelaria"}
```

```python
cursor.execute(sql, parametros)
```

É a linha que solicita a execução do comando SQL. O primeiro argumento é a estrutura; o segundo contém os valores. Neste momento, nenhuma rota da API existe: estamos preparando a ferramenta que as rotas utilizarão.

```python
return cursor.fetchall()
```

`fetchall()` recupera todas as linhas do resultado. `return` devolve esse resultado para quem chamou a função. Sem registros, o resultado será uma lista vazia.

```python
try:
    ...
finally:
    ...
```

`try` delimita o bloco em que o trabalho é tentado. `finally` executa a limpeza mesmo quando acontece um erro ou um `return`. Inicializamos `cursor = None` para poder verificar se ele chegou a ser criado antes de fechá-lo.

A abertura da conexão acontece antes do `try`: se ela falhar, não existe conexão aberta para fechar. Na etapa do POST, acrescentaremos tratamento de falhas e confirmação de transações.

## 7. Criar o primeiro GET conectado ao MySQL

### 7.1. Preparar `main.py`

Crie `main.py` na raiz e insira este primeiro bloco:

```python
import logging

from fastapi import FastAPI, HTTPException, Path, Query, Request, Response
from fastapi.responses import JSONResponse
from mysql.connector import Error as MySQLError

from database import executar_sql

app = FastAPI(title="API de produtos — Projeto Integrador II")


@app.exception_handler(MySQLError)
def erro_de_banco(request: Request, exc: MySQLError):
    logging.getLogger("uvicorn.error").error("Erro no MySQL: %s", exc)
    return JSONResponse(
        status_code=500,
        content={"detail": "Não foi possível acessar o banco de dados."},
    )


def representar_produto(produto):
    return {
        "id": produto["id"],
        "nome": produto["nome"],
        "categoria": produto["categoria"],
        "preco": format(produto["preco"], ".2f"),
    }
```

O primeiro grupo de importações reúne os recursos HTTP que utilizaremos ao longo da aula. `from database import executar_sql` importa nossa própria função.

```python
app = FastAPI(title="API de produtos — Projeto Integrador II")
```

Cria o objeto da aplicação. É nele que registraremos as rotas.

O bloco com `@app.exception_handler(MySQLError)` trata erros do driver do MySQL. Registra o detalhe no terminal e devolve uma resposta `500` com uma mensagem curta. `Request` representa a requisição e `JSONResponse` permite informar explicitamente corpo e status. O tratamento também é usado se o MySQL estiver desligado ou a senha estiver incorreta. A indicação com `@` é um **decorador**: registra a função seguinte para uma finalidade no framework.

A função `representar_produto` prepara os quatro campos que devolveremos. `produto["nome"]` lê o valor de uma chave do dicionário.

`format(produto["preco"], ".2f")` transforma o preço em texto com duas casas, por exemplo `"18.50"`. Essa é uma escolha do contrato da API para manter a representação decimal do dinheiro. O banco continua armazenando um `DECIMAL`; JSON não tem um tipo específico para valores monetários.

### 7.2. Acrescentar a rota de listagem

**Abaixo de todo o código atual de `main.py`**, acrescente:

```python
@app.get("/produtos")
def listar_produtos():
    sql = "SELECT id, nome, categoria, preco FROM produtos ORDER BY id"
    produtos = executar_sql(sql)

    return {
        "dados": [representar_produto(produto) for produto in produtos],
        "didatica": {"sql": sql, "parametros": []},
    }
```

`@app.get("/produtos")` registra a função para receber GET nesse caminho. A função executa o SELECT e devolve um dicionário, que o FastAPI serializa em JSON.

A expressão abaixo cria uma lista de representações dos produtos:

```python
[representar_produto(produto) for produto in produtos]
```

Ela percorre a lista retornada pelo banco, aplica a função a cada item e reúne os resultados. É uma **compreensão de lista**. Equivale a criar uma lista vazia e usar um laço `for` para adicionar os produtos transformados.

`dados` contém os resultados. `didatica` mostra o SQL e os valores utilizados. Este bloco é um recurso de aprendizagem para o ambiente local; em uma API publicada, não exporíamos esses detalhes internos.

## 8. Interpretar o JSON de retorno

Um exemplo abreviado:

```json
{
  "dados": [
    {
      "id": 1,
      "nome": "Caderno",
      "categoria": "Papelaria",
      "preco": "18.50"
    }
  ],
  "didatica": {
    "sql": "SELECT id, nome, categoria, preco FROM produtos ORDER BY id",
    "parametros": []
  }
}
```

| Elemento  | Leitura                            |
| --------- | ---------------------------------- |
| `{ }`     | Objeto, com propriedades e valores |
| `[ ]`     | Array: lista de elementos          |
| `"dados"` | Nome de uma propriedade            |
| `:`       | Separa nome da propriedade e valor |
| `,`       | Separa propriedades ou itens       |
| `1`       | Número inteiro                     |
| `"18.50"` | Texto, pois está entre aspas       |
| `[]`      | Lista vazia                        |

O objeto externo tem duas propriedades: `dados` e `didatica`. Em uma listagem, `dados` é um array de objetos. Cada objeto representa um produto. A propriedade `didatica` contém outro objeto, com o comando e seus parâmetros.

JSON é um formato de intercâmbio, não uma linguagem de programação nem uma tabela do MySQL. Um dicionário Python pode ser convertido para JSON, mas os dois não são a mesma coisa: por exemplo, Python usa `None`, enquanto JSON usa `null`.

> ### **Regras de JSON que você deve lembrar**
>
> - **Textos e nomes de propriedades usam aspas duplas.**
> - **Não há comentários em JSON.**
> - **Não coloque vírgula depois do último elemento.**
> - **Números decimais usam ponto, não vírgula.**
> - **Booleanos são `true` e `false`; ausência de valor é `null`.**
> - **Texto `"3"` e número `3` são valores de tipos diferentes.**
> - **No nosso contrato, o preço será exibido como texto com duas casas, por exemplo `"18.50"`.**

## 9. GET com parâmetro no caminho: consultar um produto

### 9.1. Acrescentar a operação

**Ao final de `main.py`**, sem apagar a listagem, acrescente:

```python
@app.get("/produtos/{produto_id}")
def consultar_produto(produto_id: int = Path(gt=0)):
    sql = "SELECT id, nome, categoria, preco FROM produtos WHERE id = %s"
    parametros = (produto_id,)
    produtos = executar_sql(sql, parametros)

    if not produtos:
        raise HTTPException(status_code=404, detail="Produto não encontrado")

    return {
        "dados": representar_produto(produtos[0]),
        "didatica": {"sql": sql, "parametros": list(parametros)},
    }
```

A rota contém uma parte variável: `{produto_id}`. Ao receber `/produtos/3`, o FastAPI coloca `3` no argumento `produto_id`.

```python
produto_id: int = Path(gt=0)
```

`int` declara o tipo inteiro. `Path(gt=0)` exige um valor maior que zero. A API valida a entrada antes de executar a função.

### 9.2. Entender o SQL parametrizado

```python
parametros = (produto_id,)
produtos = executar_sql(sql, parametros)
```

`(produto_id,)` é uma **tupla com um item**. A vírgula é necessária: `(produto_id)` seria apenas o valor entre parênteses.

O SQL tem um marcador `%s`, e a tupla tem o valor correspondente. `%s` é usado pelo Connector/Python mesmo para inteiros. Não coloque aspas ao redor do marcador.

| Estrutura       | Valores |
| --------------- | ------- |
| `WHERE id = %s` | `(3,)`  |

**Não use f-string nem concatenação para inserir valores recebidos do cliente no SQL.** O driver deve tratar esses valores. Isso evita misturar dados com a estrutura do comando e reduz riscos de injeção SQL.

O bloco didático mostra o comando parametrizado e os valores fornecidos ao driver; não é uma captura da comunicação interna com o banco.

```python
if not produtos:
    raise HTTPException(status_code=404, detail="Produto não encontrado")
```

Se a lista estiver vazia, interrompemos essa operação com uma resposta HTTP de erro. Caso contrário, `produtos[0]` acessa o primeiro registro; em Python, os índices começam em zero. Como `id` é chave primária, haverá no máximo um resultado.

### 9.3. Testar

Salve, aguarde o reload e atualize `/docs` no navegador para carregar o novo contrato.

1. Abra GET `/produtos/{produto_id}`.
2. Clique em **Try it out**.
3. Informe um ID existente e execute: espere `200` com um objeto em `dados`.
4. Informe um ID inexistente: espere `404` com `{"detail": "Produto não encontrado"}`.
5. Informe `0` ou `-1`: espere `422`, pois a entrada não atende à regra.

Se o formulário do Swagger impedir um texto como `abc`, esse é um controle do cliente. Para observar a validação do servidor, abra diretamente `/produtos/abc` no navegador: a API retornará `422`.

> **Conferência 3:** você consegue distinguir uma entrada inválida (`422`) de um identificador válido cujo produto não existe (`404`).

## 10. GET com parâmetro de consulta: filtrar por categoria

### 10.1. Substituir somente a função de listagem

Em `main.py`, encontre o bloco que começa com `@app.get("/produtos")` e inclui `def listar_produtos()`. **Substitua esse bloco inteiro** pela versão abaixo. Preserve a função de consulta por ID e o restante do arquivo.

Não mantenha duas operações GET registradas no mesmo caminho.

```python
@app.get("/produtos")
def listar_produtos(
    categoria: str | None = Query(default=None, min_length=1, max_length=50),
):
    sql = "SELECT id, nome, categoria, preco FROM produtos"
    parametros = ()

    if categoria is not None:
        sql += " WHERE categoria = %s"
        parametros = (categoria,)

    sql += " ORDER BY id"
    produtos = executar_sql(sql, parametros)

    return {
        "dados": [representar_produto(produto) for produto in produtos],
        "didatica": {"sql": sql, "parametros": list(parametros)},
    }
```

### 10.2. Entender o filtro

```python
categoria: str | None = Query(default=None, min_length=1, max_length=50)
```

- `str`: texto.
- `| None`: permite ausência de valor.
- `default=None`: o filtro é opcional.
- `Query`: informa regras de um parâmetro de consulta.
- `min_length` e `max_length`: limitam o tamanho quando o texto é enviado.

Se não houver categoria, o SELECT lista tudo. Se ela estiver presente, acrescentamos uma estrutura fixa, `WHERE categoria = %s`, e passamos o valor separadamente.

`+=` acrescenta texto à variável. Nesta função, a concatenação é usada apenas para trechos de SQL definidos pelo programador, não para o valor recebido.

```python
list(parametros)
```

Transforma a tupla em uma lista para apresentá-la no retorno didático.

### 10.3. Testar sem filtro e com filtro

Salve e atualize `/docs`.

Primeiro execute GET `/produtos` sem filtro. Se houver uma opção **Send empty value**, não a marque: queremos omitir o parâmetro, e não enviar texto vazio.

Depois informe `Papelaria` no campo `categoria` e execute.

A URL será semelhante a:

```text
http://127.0.0.1:8000/produtos?categoria=Papelaria
```

O SQL será:

```sql
SELECT id, nome, categoria, preco FROM produtos
WHERE categoria = %s ORDER BY id
```

E os parâmetros:

```json
["Papelaria"]
```

O `?` inicia os parâmetros de consulta. Quando existem vários, `&` os separa; não significa automaticamente AND no SQL. Trabalharemos com combinações na próxima aula.

Uma categoria sem produtos retorna `200` com `dados: []`. Diferentemente de `/produtos/999999`, estamos consultando uma coleção filtrada, que pode estar vazia.

A comparação `=` segue a collation configurada no MySQL. Algumas configurações ignoram diferenças de caixa e acentuação; portanto, não presuma que esta consulta diferencia `Informática` de `Informatica`. Estudaremos padronização dos dados depois.

| Parâmetro no caminho               | Parâmetro de consulta           |
| ---------------------------------- | ------------------------------- |
| `/produtos/3`                      | `/produtos?categoria=Papelaria` |
| Identifica um produto específico   | Filtra a coleção                |
| Obrigatório na rota correspondente | Opcional nesta implementação    |

> **Conferência 4:** a mesma rota lista todos os produtos ou somente uma categoria, e o SQL exibido muda de acordo com o filtro.
